# Zuriel AI Resume Assistant Worker

This Worker powers the AI resume assistant on Zuriel Shanley Tanyory's portfolio website.

The live website should call the Worker through the same domain:

```text
https://zurielst.com/ai/run/<encoded-message>
```

The Worker is intentionally designed to avoid public diagnostic routes.

## Required Cloudflare binding

Add a Workers AI binding named exactly:

```text
AI
```

The Worker code calls:

```js
env.AI.run(...)
```

If the binding is missing or named differently, the assistant will not work.

## Required Cloudflare route

Add this route to the Worker:

```text
zurielst.com/ai*
```

Optional if you use `www`:

```text
www.zurielst.com/ai*
```

Do not route the full website path `zurielst.com/*` to this Worker. That would intercept the static portfolio.

## Public route used by the website

The website uses only:

```text
GET /ai/run/<encoded-message>
```

The encoded message is generated by `script.js` in the static website.

## Disabled diagnostic routes

These should return a generic not-found response:

```text
/ai/health
/ai/test
/ai/cors-check
/ai/chat
/health
/test
/cors-check
/chat
```

They are disabled so the public site does not reveal model name, binding status, CORS settings, or test output.

## AI knowledge source

The model is not trained or fine-tuned on the resume. The Worker passes the `PROFILE_CONTEXT` text into the prompt at request time.

To update the assistant knowledge, update the `PROFILE_CONTEXT` block in:

```text
worker/src/index.js
```

The easiest way is to run:

```bash
./tools/update-resume.sh path/to/new-resume.pdf
```

from the project root.

On Windows PowerShell with Git Bash installed:

```powershell
bash tools/update-resume.sh "C:/Users/Zuriel/Downloads/Resume.pdf"
```

After running the tool, redeploy this Worker from the Cloudflare Dashboard.

## Dashboard deployment steps

1. Open Cloudflare Dashboard.
2. Go to **Workers & Pages**.
3. Open `zuriel-ai-resume-assistant`.
4. Click **Edit code**.
5. Paste the latest `worker/src/index.js`.
6. Click **Save and deploy**.
7. Confirm the `AI` binding still exists.
8. Confirm the route `zurielst.com/ai*` still exists.

## Security notes

- Keep the WAF exception narrow, allow only `GET /ai/run/`.
- Do not expose `/ai/health` or `/ai/test` publicly.
- Keep the rate limiting rule focused on `/ai/` if possible.
- Do not store secrets, API keys, private phone numbers, or private notes in `PROFILE_CONTEXT`.
- The Worker should return concise resume-backed answers only.

## Troubleshooting

### The assistant is unavailable

Check:

```text
AI binding exists and is named AI
Route zurielst.com/ai* exists
WAF allows GET /ai/run/
Rate limit is not blocking the request
Worker was redeployed after changes
```

### The assistant answers with old resume information

The static resume PDF may be updated, but the Worker may still be running an old `PROFILE_CONTEXT`. Redeploy `worker/src/index.js`.

### `/ai/health` returns not found

That is expected. Diagnostics are intentionally disabled.
